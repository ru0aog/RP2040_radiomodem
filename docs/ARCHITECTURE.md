# RP2040_radiomodem — архитектура  
  
Полудуплексный цифровой радиомодем на RP2040: приёмный тракт  
(наследие RP2040_receiver) и передающий тракт (наследие RP2040_beacon)  
физически раздельны и **никогда не работают одновременно**.  
  
## Ядра  
  
| Ядро  | Назначение |  
|-------|------------|  
| Core 1 | Реальное время: либо RX-конвейер (ADC+DMA → DDC → децимация → демодуляция), либо TX-генератор (модулятор → DDS/PIO). Активна одна ветка. |  
| Core 0 | Приложение: CAT/CLI (Kenwood TS-2000), декодеры + RSID, планировщик передач, файловая система/MSC, датчики, LCD. |  
  
## Переключение RX/TX  
  
Единственная точка — `trx_switch(TRX_RX | TRX_TX, freq_hz)` в  
`src/trx/trx_control.cpp`. Порядок фиксирован:  
  
1. stop активного тракта (на Core 1);  
2. `mem_arena_release()` — память ушедшей фазы мертва целиком;  
3. перенастройка VFO (hook, поддержка split);  
4. start нового тракта.  
  
Команды CAT и планировщик обязаны идти через `trx_switch()`.  
  
## Менеджер памяти (`src/mem/mem_arena.*`)  
  
Bump-аллокатор поверх статических пулов SRAM. Фазы:  
  
- `MEM_PHASE_RX` и `MEM_PHASE_TX` — **одна общая область**  
  (`MEM_TRX_POOL_SIZE`): при смене направления сбрасывается одной  
  операцией, фрагментации нет.  
- `MEM_PHASE_SHARED` — отдельная область (настройки, расписание,  
  CAT-буферы); не очищается никогда.  
  
`alloc()` из неактивной фазы — ASSERT (ловля ошибок жизненного цикла).  
Диагностика — `mem_arena_watermark()` (пиковое заполнение RX/TX-области).  
  
Стратегия миграции: большие статические буферы исходных проектов  
(DMA-буферы `rx_buf_*`, FFT-кольца 4096, метрики Витерби, GTZ-банки,  
TX-буферы символов) поэтапно переводятся с `static` на арену —  
API стабилен с первого коммита.
