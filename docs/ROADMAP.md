# ROADMAP.md — путь к радиомодему, маяку, приёмнику и BBS  
  
Документ фиксирует этапы развития RP2040_radiomodem от текущего  
состояния (рабочий RX-конвейер + каркас TX) до полноценного  
полудуплексного радиомодема с Hayes-интерфейсом, маяком и  
электронной BBS через радиоэфир.  
  
Обозначения приоритетов: **P0** — блокирует всё остальное;  
**P1** — нужно для базового модема; **P2** — нужно для BBS;  
**P3** — улучшения.  
  
Общие критерии приёмки любого этапа (регрессионный тест):  
`drop=0`, `fcsover=0`, `qfull=0`, `dead=0` в статистике захвата;  
`total` нагрузка < 800‰ на 373 МГц; отсутствие зависаний при  
прогоне `cap_isr` > 100000; PRIMASK-сторож в `loop1` не срабатывает.  
  
---  
  
## Этап 0. Стабилизация платформы (P0)  
  
Цель: устранить известные хвосты, чтобы дальнейшая разработка не  
строилась на непроверенном фундаменте.  
  
Задачи:  
  
1. Таймауты ожиданий: `while(!core1_pll_done)` и `core0_wait_in_ram`  
   — добавить второй таймаут и путь деградации (сейчас возможна  
   вечная блокировка при сбое Core 1).  
2. Убрать `Serial.println` из `rx_capture_start` (или гарантировать,  
   что старт захвата никогда не вызывается из парковочного пути).  
3. Проверить RSID после кванта DSP (коммит c208765): детект на живом  
   слабом сигнале с QSB; при деградации — `RSID_SLICE_US` 2000→1000/500  
   мкс или гибрид «таймер + пустая очередь». Эталон — `5b0a017`.  
4. Проверить UAC-аудио на хосте (`aud_fill`/`aud_drop` сейчас 0);  
   при щелчках — поднять частоту `usb_audio_poll()`.  
5. Устранить двойные init (`[RX] dsp init`, `[DEC] init`,  
   `[MSC] registering`) — добавить флаги инициализации.  
6. Разобраться с `arena watermark: 0/36864`: либо обновлять watermark,  
   либо урезать `MEM_TRX_POOL_SIZE` и вернуть SRAM.  
7. Унифицировать зашитую частоту приёма: сейчас f_rx дублируется в  
   `trx_switch` возврата, `vfo_on_trx_switch`, `cat_set_freq_hz`,  
   `rx_dsp_start` — ввести единый источник (`my_freq_rx_var`).  
  
Критерии готовности: все пункты закрыты; регрессионный тест пройден;  
RSID детектирует не хуже, чем до c208765.

## Этап 1. Полный радиотракт (P1)  
  
Цель: TX-сторона равноправна RX — переключение и передача работают  
под нагрузкой, есть аппаратный PTT.  
  
Задачи:  
  
1. Аппаратный PTT-выход: выделить GPIO, поднять/опустить вокруг  
   `trx_switch` (PTT до старта TX-генератора, снять после stop);  
   `PIN_PTT_LED` оставить индикатором.  
2. Реальные `tx_pipeline_start/stop` вместо weak-заглушек:  
   инициализация/сброс TX-таблиц в `mem_arena` TX-фазы.  
3. Тест цикла RX→TX→RX при активной JTTY (перевыделение арены,  
   восстановление NCO и демодулятора после возврата в RX).  
4. Проверка `tx_job` end-to-end: submit → QUEUED → ACTIVE → DONE,  
   abort через `tx_job_abort()` и `pc_file_written`; поведение при  
   `tx_frame == nullptr` у RX-only мод — должен быть TXJ_ERROR.  
5. Калибровка TX-мощности/уровней `soft_tx` на реальную нагрузку;  
   документировать схему подключения (ФНЧ, ключ PTT).  
  
Критерии готовности: 100 циклов RX→TX→RX без потерь захвата и без  
зависаний; abort прерывает передачу ≤ 1 символа; PTT-ключение  
проверено на железе.  
  
---  
  
## Этап 2. Протоколы связи (P1)  
  
Цель: все зарегистрированные моды полнодуплексны в рамках полудуплексного  
тракта (RX и TX), RSID работает в обе стороны.  
  
Задачи:  
  
1. Дописать `tx_frame` для RTTY, Olivia, Contestia, JTTY, IFKP —  
   посимвольная модуляция через `vfo_bank`/`soft_tx`, с проверкой  
   `tx_job_state()==TXJ_ABORTED` в цикле.  
2. Верификация AX.25: HDLC-фрейминг (bit-stuffing, FCS CRC-16,  
   флаги), NRZI, тест приёма собственной передачи (loopback через  
   второй приёмник или SDR).  
3. Верификация CW TX: тайминги дит/дах, вес, QSK-задержки.  
4. RSID-TX: передача кода моды перед `tx_frame` (стандарт RSID,  
   ~3 с преамбула); конфигурируемо через SET.TXT.  
5. Авто-переключение моды по `modes_get_by_rsid` — проверить, что  
   `rx_init` вызывается с корректным `center_hz` после детекта.  
6. Таблица совместимости: какие моды реально декодируются на живом  
   эфире (не только на генераторе) — зафиксировать в MODULES.md.  
  
Критерии готовности: каждая мода передаёт и принимает тестовый кадр;  
AX.25-кадр декодируется эталонным софтом (Dire Wolf/fldigi); RSID-TX  
распознаётся внешним декодером.  
  
---  
  
## Этап 3. Hayes-модем (P1)  
  
Цель: `src/modem/` из STUB превращается в рабочий командный слой —  
точка входа для пользователя и для BBS.  
  
Задачи:  
  
1. Парсер AT-команд в `modem_cmd_exec`: `AT`, `ATD<freq>[,<mode>]`,  
   `ATH`, `ATO`, `ATSn?`/`ATSn=v`, `AT+MODE`, `AT+FREQ`, `AT+RSID`.  
2. FSM `MODEM_COMMAND → MODEM_ONLINE → MODEM_DATA`: CONNECT по  
   успешному `tx_job`, NO CARRIER по abort/таймауту, escape `+++`  
   с guard-time (S2/S12) для возврата в COMMAND.  
3. DATA-режим: поток байт CDC → `tx_job` (пакетизация под  
   `TX_JOB_PAYLOAD_MAX`), RX-декодер → CDC.  
4. S-регистры в `modem_cfg` + персистентность через SET.TXT.  
5. Профиль Hayes поверх AX.25 для связного режима (connected mode):  
   установление/разрыв связи, I/S-кадры — база для BBS.  
  
Критерии готовности: терминал на ПК выполняет `ATD` → передача →  
`ATH`; `+++` возвращает в COMMAND без разрыва USB; два модема  
обмениваются текстом в DATA-режиме.  
  
---  
  
## Этап 4. Маяк (P2)  
  
Цель: автономные периодические передачи без участия ПК.  
  
Задачи:  
  
1. Планировщик маяка на Core 0: период, мода, текст, частота —  
   из SET.TXT (`BEACON_PERIOD`, `BEACON_MODE`, `BEACON_TEXT`,  
   `BEACON_FREQ`); submit через `tx_job`.  
2. Политика вежливости: не передавать, если канал занят (детект  
   активности по уровню в `rx_dsp` / RSID) — отложить до тишины.  
3. Поддержка CW-маяка (минимум) и одной цифровой моды (JTTY/Olivia).  
4. Логирование передач маяка в LOG.TXT.  
  
Критерии готовности: маяк работает автономно ≥ 24 ч, передачи по  
расписанию, RX-конвейер восстанавливается после каждой передачи  
(`drop=0` на протяжении всего прогона).  
  
---  
  
## Этап 5. Электронная BBS (P2)  
  
Цель: хранение и обмен сообщениями через радиоэфир — почтовый ящик  
на AX.25-сессиях.  
  
Задачи:  
  
1. Хранилище почты во flash: новый регион карты (расширить кольцо  
   состояний или выделить сектора выше 0x180000), формат записи  
   «от/кому/тема/тело/флаги», CRC на запись, переживание reset.  
   Буферы — только `mem_arena` SHARED или потоковая запись: SRAM  
   занято ~94.5%, .bss растить нельзя.  
2. AX.25 connected mode (из этапа 3.5) как транспорт сессии.  
3. Командный слой BBS поверх modem DATA: `LIST`, `READ n`,  
   `SEND <call>`, `DELETE n`, `HELP`; приглашение с позывным BBS.  
4. Маршрутизация: минимум — форвардинг сообщения другому позывному  
   при установлении связи (store-and-forward); полноценная сетевая  
   маршрутизация — за рамками этого этапа.  
5. Управление с ПК: просмотр/заливка почты через MSC-файл  
   (по образцу SET.TXT) или CLI-команды.  
  
Критерии готовности: удалённый клиент по AX.25 читает список,  
оставляет и забирает сообщения; почта переживает power-cycle;  
SRAM-футпринт BBS ≤ 4 КБ в SHARED-арене.

## Этап 6. Улучшения (P3)  
  
- AFC по `rx_dsp_set_nco_hz` от измеренного смещения (RSID/пилот).  
- CAT-расширения: переключение моды, PTT по TX-команде.  
- Ужатие RAM-диска (27 КБ) при нехватке SRAM под BBS.  
- Документирование схемы подключения трансивера (PTT, ФНЧ, аудио).  
- Перенос эталонных конфигов SET.TXT под контроль версий.
